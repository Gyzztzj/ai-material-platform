## 1. 部署概述

本文档详细介绍如何使用 Railway 免费部署 AI 素材平台后端。Railway 提供以下优势：

- **免费额度**: 适合个人项目和小型应用
- **一键部署**: 几分钟内完成部署
- **托管数据库**: PostgreSQL 和 Redis 一站式配置
- **自动 SSL**: 自动配置 HTTPS 证书
- **简单配置**: 图形化界面管理环境变量

## 2. 前置准备

### 2.1 必需条件

在开始部署之前，请确保您拥有：

- **GitHub 账号**: 用于托管代码仓库
- **Railway 账号**: 可以使用 GitHub 账号登录
- **已推送的代码仓库**: 后端代码已推送到 GitHub
- **AI 服务 API Keys**:
  - 通义万相 API Key
  - 豆包 API Key
  - Remove.bg API Key（可选）

### 2.2 仓库结构要求

确保您的仓库结构符合以下要求：

```
ai-material-platform/          # 根目录（仓库根目录）
├── ai-material/               # 前端项目目录
├── server/                    # 后端项目目录
│   ├── src/
│   ├── package.json
│   └── ...
└── docs/
```

### 2.3 本地构建测试

在部署前，建议先在本地测试构建是否正常：

```bash
cd server
pnpm install
pnpm build

# 检查是否成功生成 dist 目录
```

## 3. Railway 部署步骤

### 3.1 步骤一：登录 Railway

1. 访问 [Railway 官网](https://railway.app)
2. 点击右上角 **Login**
3. 选择 **Login with GitHub** 使用 GitHub 账号登录
4. 完成 Railway 账号创建和登录

### 3.2 步骤二：创建新项目

1. 登录后点击 **New Project**
2. 选择 **Deploy from GitHub repo**
3. 如果是第一次使用，可能需要授权 Railway 访问您的 GitHub 仓库
4. 搜索并选择您的仓库

### 3.3 步骤三：添加服务

Railway 项目创建后，按顺序添加以下服务：

#### 先添加 PostgreSQL（步骤 3.4）

#### 再添加 Redis（步骤 3.5）

#### 最后添加后端服务（步骤 3.6）

### 3.4 步骤四：添加 PostgreSQL 数据库

1. 在项目中点击 **Add Service** → **Database**
2. 选择 **PostgreSQL**
3. 等待数据库服务启动完成（通常需要 1-2 分钟）
4. 点击 PostgreSQL 服务卡片进入详情
5. 点击 **Variables** 标签页
6. 复制或记下以下信息（后续配置需要）：
   - `DATABASE_URL`

**注意**: 免费版 Railway PostgreSQL 有 500MB 存储限制。

### 3.5 步骤五：添加 Redis

1. 点击 **Add Service** → **Database**
2. 选择 **Redis**
3. 等待 Redis 服务启动完成
4. 点击 Redis 服务卡片进入详情
5. 点击 **Variables** 标签页
6. 复制或记下以下信息：
   - `REDISHOST`
   - `REDISPORT`
   - `REDISPASSWORD`
   - `REDISUSER`

**注意**: 免费版 Railway Redis 有 50MB 存储限制。

### 3.6 步骤六：添加后端服务

1. 点击 **Add Service** → **GitHub Repo**
2. 选择您的仓库
3. 配置服务设置：

#### 3.6.1 基本设置

| 设置项             | 配置值                            | 说明                   |
| ------------------ | --------------------------------- | ---------------------- |
| **Service Name**   | `ai-material-backend`（或自定义） | 服务名称               |
| **Root Directory** | `server`                          | 后端项目在仓库中的目录 |

#### 3.6.2 构建和启动命令

| 设置项            | 配置值                       |
| ----------------- | ---------------------------- |
| **Build Command** | `pnpm install && pnpm build` |
| **Start Command** | `node dist/main.js`          |

#### 3.6.3 环境变量（步骤 6 详细配置）

先点击 **Deploy** 部署一次，等会儿再配置环境变量。

## 4. PostgreSQL 数据库配置

### 4.1 连接信息

部署 PostgreSQL 后，可以在 Variables 中找到：

| 变量名         | 说明             |
| -------------- | ---------------- |
| `PGHOST`       | 数据库主机地址   |
| `PGPORT`       | 数据库端口       |
| `PGUSER`       | 数据库用户名     |
| `PGPASSWORD`   | 数据库密码       |
| `PGDATABASE`   | 数据库名称       |
| `DATABASE_URL` | 完整的连接字符串 |

### 4.2 本地连接（可选）

如果需要本地连接到 Railway PostgreSQL 进行调试：

```bash
# 使用 psql 连接
psql your_database_url

# 或使用其他 PostgreSQL 客户端工具（如 pgAdmin、DBeaver 等）
```

### 4.3 数据库备份

Railway 提供自动备份功能：

1. 进入 PostgreSQL 服务页面
2. 点击 **Backups** 标签页
3. 可以查看和恢复自动备份
4. 也可以创建手动备份

#### 使用 pg_dump 手动备份

```bash
# 备份数据库
pg_dump "$DATABASE_URL" > backup.sql

# 从备份恢复
psql "$DATABASE_URL" < backup.sql
```

## 5. Redis 配置

### 5.1 连接信息

部署 Redis 后，可以在 Variables 中找到：

| 变量名          | 说明           |
| --------------- | -------------- |
| `REDISHOST`     | Redis 主机地址 |
| `REDISPORT`     | Redis 端口     |
| `REDISPASSWORD` | Redis 密码     |
| `REDISUSER`     | Redis 用户名   |

### 5.2 本地连接（可选）

如果需要本地连接到 Railway Redis：

```bash
# 使用 redis-cli 连接（需要在本地安装）
redis-cli -h $REDISHOST -p $REDISPORT -a $REDISPASSWORD --user $REDISUSER
```

### 5.3 Redis 持久化

Railway Redis 提供持久化存储，重启后数据不会丢失。

## 6. 环境变量配置

### 6.1 配置步骤

1. 进入后端服务页面
2. 点击 **Variables** 标签页
3. 点击 **New Variable** 添加环境变量
4. 或点击 **Raw Editor** 批量添加

### 6.2 完整环境变量列表

| 变量名              | 示例值                                             | 是否必需 | 说明                                           |
| ------------------- | -------------------------------------------------- | -------- | ---------------------------------------------- |
| `PORT`              | `3000`                                             | 否       | Railway 会自动设置                             |
| `NODE_ENV`          | `production`                                       | 否       | Node.js 环境                                   |
| `DATABASE_URL`      | `postgresql://...`                                 | 是       | PostgreSQL 连接字符串                          |
| `DATABASE_SSL`      | `true`                                             | 是       | 必须设为 true 以支持 Railway 的 SSL 连接       |
| `REDIS_HOST`        | `redis-...`                                        | 是       | Redis 主机（从 Redis 变量复制 REDISHOST）      |
| `REDIS_PORT`        | `6379`                                             | 是       | Redis 端口（从 Redis 变量复制 REDISPORT）      |
| `REDIS_PASSWORD`    | `...`                                              | 是       | Redis 密码（从 Redis 变量复制 REDISPASSWORD）  |
| `REDIS_DB`          | `0`                                                | 是       | Redis 数据库编号                               |
| `JWT_SECRET`        | `your-strong-secret-key-here-change-in-production` | 是       | JWT 签名密钥，请使用强随机字符串，至少 32 字符 |
| `JWT_EXPIRES_IN`    | `7d`                                               | 否       | JWT Token 过期时间                             |
| `TONGYI_API_KEY`    | `sk-...`                                           | 是       | 通义万相 API Key                               |
| `DOUBAI_API_KEY`    | `...`                                              | 是       | 豆包 API Key                                   |
| `REMOVE_BG_API_KEY` | `...`                                              | 否       | Remove.bg API Key（可选）                      |
| `LOG_LEVEL`         | `info`                                             | 否       | 日志级别                                       |

### 6.3 Railway 变量引用（推荐）

Railway 支持在一个服务中引用另一个服务的变量，这样更简洁安全：

#### 使用变量引用（推荐）

不需要手动复制连接信息，直接引用：

| 变量名           | 值                           |
| ---------------- | ---------------------------- |
| `DATABASE_URL`   | `${{Postgres.DATABASE_URL}}` |
| `DATABASE_SSL`   | `true`                       |
| `REDIS_HOST`     | `${{Redis.REDISHOST}}`       |
| `REDIS_PORT`     | `${{Redis.REDISPORT}}`       |
| `REDIS_PASSWORD` | `${{Redis.REDISPASSWORD}}`   |

这样当数据库连接信息变化时，不需要手动更新后端服务的环境变量。

### 6.4 JWT_SECRET 生成建议

使用强随机字符串作为 JWT_SECRET，可以使用以下方式生成：

```bash
# 方式一：在 Linux/macOS 终端运行
openssl rand -base64 32

# 方式二：使用 Node.js 生成
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"

# 方式三：使用在线工具（不推荐生产环境使用）
```

### 6.5 保存和重部署

1. 保存所有环境变量后
2. 返回服务页面
3. 点击 **Deploy** 重新部署
4. 等待部署完成

## 8. 数据迁移

### 8.1 当前模式说明

当前项目使用 TypeORM 的 `synchronize: true` 模式，会在应用启动时自动创建和更新表结构。

这种方式适合开发和测试环境，但不推荐生产环境使用。

### 8.2 生产环境建议

对于生产环境，建议改用 TypeORM 迁移：

#### 步骤一：配置 TypeORM

确保 `server/src/data-source.ts`（或类似文件）配置正确。

#### 步骤二：创建迁移

```bash
cd server

# 生成迁移文件
pnpm typeorm-ts-node-commonjs migration:generate src/migrations/InitialMigration -d src/data-source.ts

# 或使用 npm 脚本（如果已配置）
pnpm migration:generate src/migrations/InitialMigration
```

#### 步骤三：应用迁移

```bash
# 运行迁移
pnpm typeorm-ts-node-commonjs migration:run -d src/data-source.ts

# 或使用 npm 脚本
pnpm migration:run
```

#### 步骤四：修改配置

在生产环境设置中，将 `synchronize` 改为 `false`。

### 8.3 Railway 环境运行迁移

在 Railway 环境中运行迁移：

1. 进入后端服务页面
2. 点击 **Settings**
3. 找到 **Deploy Start Command** 或修改启动脚本
4. 或在部署前在本地运行迁移

## 9. 常见问题

### 9.1 部署失败常见原因

#### 问题：构建失败，提示找不到模块

**解决方案**:

- 检查 `package.json` 中 dependencies 是否包含所有必需包
- 确认 `node_modules` 已添加到 `.gitignore`
- 检查构建命令是否正确

#### 问题：服务启动失败，数据库连接错误

**解决方案**:

- 确认 `DATABASE_URL` 配置正确
- 确认 `DATABASE_SSL` 设为 `true`
- 检查 PostgreSQL 服务是否正常运行
- 查看服务日志获取详细错误信息

#### 问题：Redis 连接失败

**解决方案**:

- 确认 Redis 相关环境变量配置正确
- 检查 Redis 服务是否正常运行
- 查看服务日志获取详细错误信息

### 9.2 环境变量相关

#### 问题：修改环境变量后未生效

**解决方案**:

- 修改环境变量后必须重新部署
- 确认修改已保存
- 查看部署日志确认新配置已生效

#### 问题：如何区分不同环境的配置

**解决方案**:

- 在 Railway 中可以创建不同的环境（如 Development、Production）
- 每个环境可以有独立的环境变量配置
- 使用 Railway 的 Environments 功能

### 9.3 数据库相关

#### 问题：数据库表没有自动创建

**解决方案**:

- 确认 `synchronize` 设置为 `true`（开发环境）
- 检查 TypeORM 配置是否正确
- 查看服务日志中是否有数据库相关错误

#### 问题：如何清理数据库重新开始

**解决方案**:

1. 进入 PostgreSQL 服务页面
2. 点击 **Settings**
3. 选择 **Delete All Data**
4. 确认删除
5. 重启后端服务，让 TypeORM 重新创建表

**警告**: 此操作会删除所有数据！

### 9.4 性能和优化

#### 问题：如何优化数据库查询性能

**解决方案**:

- 确保常用查询字段有索引
- 使用 Redis 缓存热点数据
- 避免 N+1 查询问题
- 分析慢查询并优化

#### 问题：文件存储问题

**解决方案**:

- Railway 容器重启后，本地文件系统的内容会丢失
- 建议改用云对象存储（如阿里云 OSS、AWS S3、Cloudinary 等）
- 或使用 Redis 临时缓存小文件

### 9.5 部署和 CI/CD

#### 问题：如何设置自动部署

**解决方案**:
Railway 默认配置为：

- 推送到 `main` 或 `master` 分支 → 自动部署
- 可以在服务设置 → **GitHub** 中调整这些设置

#### 问题：如何查看部署日志

**解决方案**:

1. 进入服务页面
2. 点击 **Logs** 标签
3. 查看实时日志或历史部署日志

#### 问题：如何回滚到旧版本

**解决方案**:

1. 进入服务页面
2. 点击 **Deployments** 标签
3. 找到要回滚的部署记录
4. 点击三个点菜单 → **Rollback to this deployment**

### 9.6 其他问题

#### 问题：超过免费额度怎么办

**解决方案**:

- 查看 Railway 控制台的用量统计
- 考虑升级到付费计划
- 或优化资源使用（如清理数据库、缓存等）

#### 问题：如何删除项目

**解决方案**:

1. 进入项目设置页面
2. 滚动到底部
3. 点击 **Delete Project**
4. 确认删除
