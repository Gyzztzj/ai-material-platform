## 1. 部署概述

本文档详细介绍如何使用 Vercel 免费部署 AI 素材平台前端。Vercel 提供以下优势：

- **免费额度**: 适合个人项目和小型应用
- **自动部署**: 每次推送到 GitHub 自动触发部署
- **全球 CDN**: 快速的内容分发网络
- **HTTPS 支持**: 自动配置 SSL 证书
- **预览功能**: 每个 Pull Request 生成预览链接

## 2. 前置准备

### 2.1 必需条件

在开始部署之前，请确保您拥有：

- **GitHub 账号**: 用于托管代码仓库
- **Vercel 账号**: 可以使用 GitHub 账号直接登录
- **已推送的代码仓库**: 前端代码已推送到 GitHub

### 2.2 仓库结构要求

确保您的仓库结构符合以下要求：

```
ai-material-platform/          # 根目录（仓库根目录）
├── ai-material/               # 前端项目目录
│   ├── src/
│   ├── package.json
│   └── ...
├── server/                    # 后端项目目录
└── docs/
```

### 2.3 本地构建测试

在部署前，建议先在本地测试构建是否正常：

```bash
cd ai-material
pnpm install
pnpm build

# 检查是否成功生成 dist 目录
```

## 3. Vercel 部署步骤

### 3.1 步骤一：登录 Vercel

1. 访问 [Vercel 官网](https://vercel.com)
2. 点击右上角 **Sign Up** 或 **Log In**
3. 选择 **Continue with GitHub** 使用 GitHub 账号登录
4. 完成 Vercel 账号创建和登录

### 3.2 步骤二：创建新项目

1. 登录后点击 **Add New...** → **Project**
2. 在 **Import Git Repository** 列表中找到您的仓库
3. 点击 **Import** 导入项目

### 3.3 步骤三：配置项目

在项目配置页面，填写以下信息：

#### 3.3.1 项目设置

| 设置项 | 配置值 | 说明 |
|--------|--------|------|
| **Project Name** | `ai-material-platform`（或自定义） | 项目名称，将用于生成默认域名 |
| **Root Directory** | `ai-material` | 前端项目在仓库中的目录 |
| **Framework Preset** | `Vite` | Vercel 会自动检测到 |

#### 3.3.2 构建和输出设置

Vercel 应该会自动检测到正确的配置，但请确认：

| 设置项 | 配置值 |
|--------|--------|
| **Build Command** | `pnpm build` |
| **Output Directory** | `dist` |
| **Install Command** | `pnpm install` |

#### 3.3.3 环境变量

在 **Environment Variables** 部分添加：

| 变量名 | 值 | 说明 |
|--------|-----|------|
| `VITE_API_URL` | `https://your-backend-url.railway.app` | 后端 API 地址（Railway 部署后获得） |

**注意**: 如果后端还没有部署，可以先留空或填入临时地址，后续在 Vercel 项目设置中更新。

### 3.4 步骤四：部署项目

1. 确认所有配置无误
2. 点击 **Deploy** 开始部署
3. 等待部署完成（通常需要 1-3 分钟）

### 3.5 步骤五：查看部署结果

部署成功后，Vercel 会显示：

- 项目概览页面
- 部署状态：`Production`
- 访问链接：类似 `https://ai-material-platform-abc123.vercel.app`

## 4. 环境变量配置

### 4.1 在 Vercel 项目设置中配置

1. 进入 Vercel 项目页面
2. 点击 **Settings** 标签页
3. 在左侧菜单中选择 **Environment Variables**
4. 添加或更新环境变量

### 4.2 完整的环境变量列表

| 变量名 | 是否必需 | 示例值 | 说明 |
|--------|---------|--------|------|
| `VITE_API_URL` | 是 | `https://ai-material-backend.up.railway.app` | 后端 API 地址 |

### 4.3 更新环境变量后的重部署

修改环境变量后需要重新部署才能生效：

1. 在项目页面点击 **Deployments** 标签
2. 点击最新部署记录右侧的三个点
3. 选择 **Redeploy**
4. 确认重新部署

## 5. 自定义域名配置

### 5.1 步骤一：添加自定义域名

1. 进入 Vercel 项目页面
2. 点击 **Settings** → **Domains**
3. 在 **Add Domain** 输入框中输入您的域名
4. 点击 **Add** 按钮

### 5.2 步骤二：配置 DNS

Vercel 会提供两种配置方式：

#### 选项 A：使用 Vercel DNS（推荐）

1. 将域名的 Nameservers 修改为 Vercel 提供的：
   - `ns1.vercel-dns.com`
   - `ns2.vercel-dns.com`
2. 在域名注册商处修改 Nameserver 配置
3. 等待 DNS 生效（可能需要几个小时）

#### 选项 B：使用 A 记录

1. 在您的 DNS 管理后台添加以下记录：
   - **A 记录**：`@` → `76.76.21.21`
   - **A 记录**：`www` → `76.76.21.21`
2. 或者使用 CNAME 记录指向 Vercel 分配的域名

### 5.3 步骤三：验证域名配置

1. 返回 Vercel Domains 设置页面
2. Vercel 会自动检测 DNS 配置
3. 配置成功后状态会显示为 `Valid Configuration`
4. HTTPS 证书会自动签发和配置

### 5.4 设置重定向

可以配置域名重定向，例如：

- 将 `www.yourdomain.com` 重定向到 `yourdomain.com`
- 或将 HTTP 重定向到 HTTPS

在 Domains 设置页面可以进行这些配置。

## 6. 部署验证

### 6.1 基本功能验证

部署完成后，请验证以下功能：

1. **访问首页**: 打开部署后的链接，确认页面正常加载
2. **查看控制台**: 检查浏览器开发者工具的 Console 标签页是否有错误

4. **页面路由**: 测试各页面路由跳转是否正常

### 6.2 完整流程验证

如果后端也已部署，完成以下测试：

1. **用户注册/登录**: 测试认证流程
2. **AI 生成**: 测试图片生成功能
3. **素材上传**: 测试素材上传和管理
4. **任务状态**: 测试任务状态轮询和更新

### 6.3 性能检查

使用以下工具检查性能：

- [Lighthouse](https://developer.chrome.com/docs/lighthouse/overview/): Chrome 开发者工具内置

## 7. 常见问题

### 7.1 部署失败常见原因

#### 问题：构建失败，提示找不到模块

**解决方案**:
- 检查 `package.json` 中 dependencies 是否包含所有必需包
- 确认 `node_modules` 已添加到 `.gitignore`
- 检查构建命令是否正确

#### 问题：部署成功但页面空白或报错

**解决方案**:
- 检查 `VITE_API_URL` 环境变量是否正确配置
- 检查浏览器控制台的错误信息
- 确认后端 API 可正常访问

#### 问题：刷新页面显示 404 错误

**解决方案**:
需要在前端项目中添加路由重写配置。在 `ai-material` 目录创建 `vercel.json`：

```json
{
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ]
}
```

将此文件提交并推送，Vercel 会自动重新部署。

### 7.2 环境变量相关

#### 问题：环境变量未生效

**解决方案**:
- 确认环境变量已正确添加到 Vercel 项目设置
- 环境变量名必须以 `VITE_` 开头才能在客户端访问
- 修改后需要重新部署

#### 问题：如何区分不同环境的配置

**解决方案**:
- 在 Vercel 项目设置中可以为 Preview 和 Production 设置不同的环境变量
- 或使用 Git 分支对应不同环境

### 7.3 部署和 CI/CD

#### 问题：如何自动部署

**解决方案**:
Vercel 默认配置为：
- 推送到 `main` 或 `master` 分支 → 部署到 Production
- 推送 Pull Request → 自动创建 Preview 部署
- 可以在项目设置 → Git Integration 中调整这些设置

#### 问题：如何查看部署日志

**解决方案**:
1. 进入项目页面
2. 点击 **Deployments** 标签
3. 选择要查看的部署记录
4. 点击 **View Logs** 查看详细日志

### 7.4 性能和优化

#### 问题：如何优化部署性能

**解决方案**:
- 确保 Vite 配置正确
- 使用路由懒加载（React.lazy）
- 图片压缩和优化
- 启用 Vercel 内置的优化功能

#### 问题：图片加载缓慢

**解决方案**:
- 使用图片 CDN（如 Cloudinary、阿里云 OSS 等）
- 启用图片懒加载
- 使用 WebP 等现代图片格式
- 配置合理的缓存策略

### 7.5 其他问题

#### 问题：部署后如何回滚到旧版本

**解决方案**:
1. 在 **Deployments** 页面找到要回滚的版本
2. 点击右侧三个点
3. 选择 **Promote to Production** 回滚

#### 问题：如何删除项目

**解决方案**:
1. 进入项目设置页面
2. 滚动到底部
3. 点击 **Delete Project**
4. 确认删除
