## 1. 部署概述

本文档详细介绍如何使用 Railway 免费部署 AI 素材平台前端。Railway 提供以下优势：

- **免费额度**：适合个人项目和小型应用
- **自动部署**：每次推送到 GitHub 自动触发部署
- **全球 CDN**：快速的内容分发网络
- **HTTPS 支持**：自动配置 SSL 证书
- **预览功能**：每个 Pull Request 生成预览链接

## 2. 前置准备

### 2.1 必需条件

在开始部署之前，请确保您拥有：

- **GitHub 账号**：用于托管代码仓库
- **Railway 账号**：可以使用 GitHub 账号直接登录
- **已推送的代码仓库**：代码已推送到 GitHub
- **后端服务已部署**：获取后端 API 地址

### 2.2 仓库结构要求

确保您的仓库结构符合以下要求：

```
ai-material-platform/          # 根目录（仓库根目录）
├── ai-material/               # 前端项目目录
│   ├── src/
│   ├── package.json
│   ├── railway.json
│   └── ...
├── server/                    # 后端项目目录
└── docs/
```

### 2.3 本地构建测试

在部署前，建议先在本地测试构建是否正常：

```bash
cd ai-material
pnpm install
pnpm build

# 检查是否成功生成 dist 目录
```

## 3. Railway 部署步骤

### 3.1 步骤一：登录 Railway

1. 访问 [Railway 官网](https://railway.app)
2. 点击右上角 **Login**
3. 选择 **Login with GitHub** 使用 GitHub 账号登录
4. 完成 Railway 账号创建和登录

### 3.2 步骤二：创建新项目

1. 登录后点击 **New Project**
2. 选择 **Deploy from GitHub repo**
3. 如果是第一次使用，可能需要授权 Railway 访问您的 GitHub 仓库
4. 搜索并选择您的仓库

### 3.3 步骤三：配置前端服务

#### 3.3.1 基本配置

- **Service Name**：`ai-material-frontend`（或自定义）
- **Root Directory**：`ai-material`
- **Branch**：选择您的主分支（如 `main` 或 `master`）

#### 3.3.2 构建和启动命令

Railway 的 Nixpacks 会自动检测 Vite 项目，通常不需要额外配置。但可以确认：

- **Build Command**：`pnpm install && pnpm build`
- **Start Command**：`pnpm preview`（或使用 nginx 托管静态文件）

#### 3.3.3 环境变量

在 **Variables** 部分添加：

| 变量名 | 值 | 说明 |
|--------|-----|------|
| `VITE_API_URL` | `https://your-backend-url.railway.app/api` | 后端 API 地址（注意需要添加 `/api` 前缀） |

先点击 **Deploy** 部署一次，等会儿再配置环境变量。

### 3.4 步骤四：部署成功

部署成功后，Railway 会生成一个域名，类似：
`https://ai-material-frontend-production.up.railway.app`

您可以在服务设置中自定义域名。

## 4. 环境变量配置

### 4.1 在 Railway 项目设置中配置

1. 进入 Railway 前端服务页面
2. 点击 **Variables** 标签
3. 点击 **New Variable** 添加环境变量

### 4.2 完整的环境变量列表

| 变量名 | 是否必需 | 示例值 | 说明 |
|--------|---------|--------|------|
| `VITE_API_URL` | 是 | `https://ai-material-backend.up.railway.app/api` | 后端 API 地址（注意需要添加 `/api` 前缀） |

### 4.3 更新环境变量后的重部署

修改环境变量后 Railway 会自动重新部署。

## 5. 自定义域名配置

### 5.1 步骤一：添加自定义域名

1. 进入 Railway 前端服务页面
2. 点击 **Settings** → **Domains**
3. 点击 **+ New Domain**
4. 输入您的域名，如 `app.yourdomain.com`
5. 点击 **Add Domain**

### 5.2 步骤二：配置 DNS

Railway 会提供 DNS 配置信息：

1. 登录您的域名注册商（如 Cloudflare、阿里云等）
2. 添加 CNAME 记录，指向 Railway 提供的域名
3. 等待 DNS 生效（可能需要几分钟到几小时）

### 5.3 步骤三：验证域名配置

Railway 会自动验证域名配置并颁发 HTTPS 证书。

## 6. 部署验证

### 6.1 基本功能验证

部署完成后，请验证以下功能：

1. **访问首页**：打开部署后的链接，确认页面正常加载
2. **查看控制台**：检查浏览器开发者工具的 Console 标签页是否有错误
3. **检查网络请求**：查看 Network 标签页，确认 API 请求的 URL 正确
4. **页面路由**：测试各页面路由跳转是否正常

### 6.2 完整流程验证

如果后端也已部署，完成以下测试：

1. **用户注册/登录**：测试认证流程
2. **AI 生成**：测试图片生成功能
3. **素材上传**：测试素材上传和管理
4. **任务状态**：测试任务状态轮询和更新

### 6.3 性能检查

使用以下工具检查性能：

- [Lighthouse](https://developer.chrome.com/docs/lighthouse/overview/)：Chrome 开发者工具内置

## 7. 常见问题

### 7.1 部署失败常见原因

#### 问题：构建失败，提示找不到模块

**解决方案**：
- 检查 `package.json` 中 dependencies 是否包含所有必需包
- 确认 `node_modules` 已添加到 `.gitignore`
- 检查构建命令是否正确
- 查看 Railway 部署日志

#### 问题：部署成功但页面空白或报错

**解决方案**：
- 检查 `VITE_API_URL` 环境变量是否正确配置（需要包含 `/api` 前缀）
- 检查浏览器控制台的错误信息
- 确认后端 API 可正常访问
- 检查 CORS 配置

#### 问题：刷新页面显示 404 错误

**解决方案**：

需要配置 SPA 路由重定向。在 `ai-material` 目录创建 `static.json`：

```json
{
  "root": "dist/",
  "clean_urls": true,
  "routes": {
    "/**": "index.html"
  }
}
```

或者使用 Nginx 配置：

```nginx
location / {
  try_files $uri $uri/ /index.html;
}
```

### 7.2 环境变量相关

#### 问题：环境变量未生效

**解决方案**：
- 确认环境变量已正确添加到 Railway 服务设置
- 环境变量名必须以 `VITE_` 开头才能在客户端访问
- 等待 Railway 自动重新部署

### 7.3 部署和 CI/CD

#### 问题：如何自动部署

**解决方案**：
Railway 默认配置为推送到指定分支自动部署。可以在服务设置 → **GitHub** 中调整这些设置。

#### 问题：如何查看部署日志

**解决方案**：
1. 进入服务页面
2. 点击 **Deployments** 标签
3. 选择要查看的部署记录
4. 点击 **View Logs** 查看详细日志

### 7.4 性能和优化

#### 问题：如何优化部署性能

**解决方案**：
- 确保 Vite 配置正确
- 使用路由懒加载（React.lazy）
- 图片压缩和优化
- 启用 Railway 内置的优化功能

#### 问题：图片加载缓慢

**解决方案**：
- 使用图片 CDN（如 Cloudinary、阿里云 OSS 等）
- 启用图片懒加载
- 使用 WebP 等现代图片格式
- 配置合理的缓存策略

### 7.5 其他问题

#### 问题：部署后如何回滚到旧版本

**解决方案**：
1. 在 **Deployments** 页面找到要回滚的版本
2. 点击右侧三个点
3. 选择 **Redeploy** 重新部署该版本

#### 问题：如何删除服务

**解决方案**：
1. 进入服务设置页面
2. 滚动到底部
3. 点击 **Delete Service**
4. 确认删除
